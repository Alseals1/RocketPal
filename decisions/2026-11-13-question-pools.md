# Question pools, levels and shuffled answers

Date: 2026-11-13. Decided by the Plan agent for issue #45 and built by the Implement agent. Item 10 was a small change made during the build, and item 11 came from review round 1. A person can overrule any line at PR review. The code is in `src/data/quizzes.ts`, `src/data/random.ts`, `src/data/content.ts` and `src/screens/arrivalScreen.ts`. The types are in `docs/TECHNICAL_ARCHITECTURE.md` section 4.10.

## What was decided
1. **`quizzes.json` is `{ lastChecked, pools: QuestionPool[] }`**, and each pool is `{ place, format, questions }` with a `level` on every question, exactly as 4.10 writes it (`place`, not the old `worldId`). `Content.quizzes` is `Map<PlaceId, QuestionPool>`, as 4.2 already said. `QuizQuestion` and `QuizOption` moved from `src/quiz/quiz.ts` to `src/data/quizzes.ts`, which removed the `data/quizzes` → `quiz` entry from the architecture test's allow-list.
2. **The seeded randomness lives in the Content layer** (`src/data/random.ts`: mulberry32 and a Fisher-Yates `shuffled`), next to `drawQuestions`, which 4.10 puts in `data/`. Content may import nothing but Content, so the draw cannot use a helper from elsewhere.
3. **Levels by rank:** ranks 1-4 draw only levels 1 and 2. From rank 5 (`POOL_RULES.level3FromRank`) a quiz has exactly one level-3 question when the pool has one, in a random position; a postcard draws from every level. Drawing from all levels at rank 5 without a guarantee would leave about 40% of rank-5 Mars quizzes with no harder question, so "harder at a higher rank" would not be dependable.
4. **The seed comes from `Math.random()`, once, in the arrival screen** (Screens layer), and steps forward on every draw. It only decides which questions come up and the order of questions and answers. Stars and XP are earned exactly as before (`quizFinished` with `firstTryAll`), so the rule "nothing random in rewards" holds. Rejected: a saved play counter (a save change that stores more data, for nothing), the clock (no better, and two opens in one millisecond would match), and a test-only seed in the debug handle (the e2e tests read the screen instead).
5. **`drawDifferent`** tries `seed`, `seed + 1` and so on (at most 20 tries) until the draw differs from the last one on that place: other questions, another order, or another answer order. The arrival screen keeps the last draw per place for as long as the game runs, so "Play again", "Quiz time" after "Not now", and a later visit are all a new quiz. The rank is read when the quiz opens, so a kid who ranks up gets the harder mix on the next go.
6. **What is dropped:** a single bad question is reported and left out on its own, and the rest of its pool loads. A pool is dropped only when it is not an object, has no landing picture, has a bad `format`, has no question list, or has good questions at levels 1 and 2 on too few dots to fill a draw (3 dots for a quiz, 1 for a postcard; see item 11). The size rule (6-9 for a quiz, 2-4 for a postcard), the "same position" rule and the "longest answer" rule are reported but keep the pool. Every check that ran on the old fixed quiz runs on every pool question, with the same messages, plus "level must be 1, 2 or 3" and "asks the same question as another one in this pool". The console wording ("Some quizzes were left out:") is unchanged.
7. **The "longest answer" rule is now "at most a third of a pool (rounded down)"**, instead of "not in every question". With 8 or 9 questions, "not in all of them" would let it give the answer away almost every time. The "same position" rule stays although answers are now shuffled: the issue asks for every existing check to stay, and it still protects the data if shuffling is ever turned off.
8. **Pools shipped:** Mars 8 (3 at level 1, 3 at level 2, 2 at level 3) and Earth 9 (3, 4, 2). Every new question restates a fact already in one of the world's dots, whose NASA sources were checked on 2026-10-23. No dot text changed.
9. **The NASA read is an open item before `dev` → `main`.** This repo runs on autopilot, so no person reads the PR before it merges. `docs/PROGRESS.md` tracks the read of the 11 new questions; `lastChecked` stays 2026-10-23 until a person does it.
10. **`earth-clouds` and `earth-oceans` swap "because" lines (build change).** The plan gave `earth-clouds` the line "Earth's oceans cover about 71 percent of the planet." Both questions come from the clouds dot and can be drawn in the same quiz, so that line would give away the `earth-oceans` answer. `earth-clouds` now says "Most of our planet is covered in water!" and `earth-oceans` says the 71 percent line. Same dot, same facts.
11. **One question per dot in a draw (review round 1).** Two questions on the same dot can give each other away: `mars-lake`'s "because" line answers `mars-lake-age`, and `mars-lake-age`'s question answers `mars-lake` (about 20% of rank-1 Mars draws had both). `mars-rover`/`mars-rover-job`, `earth-aurora-oxygen`/`earth-aurora`, `mars-sky`/`mars-sky-color` and `earth-air`/`earth-air-shield` had the same risk. So `drawQuestions` never puts two questions on one dot in the same draw, and `checkPool` counts the distinct dots at levels 1 and 2 (not the questions) for the "enough to fill a draw" rule, which keeps every valid pool able to fill a draw with one question per dot, at every rank. Only a pool that skipped validation may share a dot, and only when it cannot fill a draw otherwise. Rejected: rewording each pair so no line names a sibling's answer, because every new question on a dot would need the same care by hand, and a test cannot tell when a reworded line still gives an answer away.

## Why
- A replayed quiz used to be the same three questions in the same order, so the first-try bonus star could be earned from memory. Pools with levels make a replay a new quiz, make higher ranks a little harder, and leave room for fly-by postcards later with the same code.

## Alternatives
- **Drop the whole pool for one bad question (today's behaviour):** a typo in one of nine questions would remove the world's quiz.
- **Draw in the quiz panel (UI layer):** the draw is a content rule and 4.10 puts it in `data/`; the panel only asks for a draw through a callback.
- **No guaranteed difference on replay (trust the randomness):** about one replay in a few dozen would repeat exactly, and the e2e test for it would flake.
